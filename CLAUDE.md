# Junbi Backend — CLAUDE.md

## What This Service Does

FastAPI backend for the Junbi kitchen assistant app. Handles pantry tracking, recipe management, grocery list generation, AI-powered food scanning, and a LangGraph agent that orchestrates end-to-end grocery ordering via Instacart.

---

## Stack

| Layer | Technology |
|---|---|
| Framework | FastAPI + Uvicorn |
| Language | Python 3.13 |
| Database | Supabase PostgreSQL |
| DB Driver | psycopg v3 (async pool) — **no ORM** |
| Migrations | dbmate |
| Auth | Firebase Admin SDK (token verification) |
| AI | Anthropic Claude API |
| Agent | LangGraph (StateGraph) |
| Config | Pydantic BaseSettings from `.env` |

## Database

**No ORM.** All queries use raw parameterized SQL via psycopg v3:

```python
async with pool.connection() as conn:
    async with conn.cursor(row_factory=dict_row) as cur:
        await cur.execute(
            "SELECT * FROM pantry_items WHERE user_id = %s",
            (user_id,),
        )
        rows = await cur.fetchall()
```

**Rules:**
- Always use `%s` placeholders — never f-strings or `.format()` in SQL
- `dict_row` row factory — queries return dicts, not tuples
- Async pool only in routes; the agent's `load_context` node uses a separate async pool
- Migrations live in `db/migrations/` — run `make migrate` to apply
- `db/schema.sql` is auto-generated by dbmate — never edit it manually
- `draft_schema.sql` is the source of truth for reviewing schema state
- **Naming:** DB columns are `snake_case`; API JSON keys are `camelCase` — map in the route

**Key tables:** `user_profiles`, `user_preferences`, `user_addresses`, `pantry_items`, `ingredients`, `recipes`, `grocery_lists`, `grocery_list_items`, `orders`, `connected_accounts`

## Authentication

Every endpoint (except `GET /health`) requires Firebase auth.

**Flow:**
1. Frontend sends `Authorization: Bearer <Firebase ID token>`
2. `get_current_user()` in `app/core/dependencies.py` verifies the token with Firebase Admin
3. Extracts `uid` + `email` from decoded token
4. Auto-creates `user_profiles` + `user_preferences` rows if first visit
5. Returns full user dict (with addresses, preferences, connected accounts)

**In routes:**
```python
@router.get("/me")
async def get_me(
    current_user: dict = Depends(get_current_user),
    db=Depends(get_db),
):
    ...
```

## API Conventions

- **Prefix per domain:** `/users`, `/pantry`, `/recipes`, `/grocery`, `/orders`, `/agents`, etc.
- **JSON keys:** camelCase in request/response bodies — map from snake_case DB columns in the route handler
- **Error responses:** `HTTPException(status_code=..., detail="...")` — FastAPI standard
- **Schemas:** Pydantic models in `app/schemas/` for request bodies; response dicts built inline
- **CORS:** `allow_origins=["*"]` currently — fine for dev, restrict before production launch

## Smart Grocery Agent (LangGraph)

**Graph nodes (in order):**
1. `load_context` — 5 parallel async DB queries (pantry, recipes, grocery list, preferences, addresses)
2. `resolve_stores` — calls Instacart service, scores stores by budget + dietary tags
3. `analyze_pantry` — Claude identifies what to buy (gaps from recipes, expiring items, staples)
4. `search_store` — searches store catalog via Instacart TS bridge
5. `compare_prices` — estimates cart total across Walmart, Costco, Kroger, Publix, Whole Foods, Aldi
6. `build_cart` — Claude selects best products per item with budget awareness
7. `human_checkpoint` — **interrupts graph** — returns to frontend for user review + store override
8. `place_order` — executes Instacart checkout, returns checkout URL for WebView
9. `finalize` — writes confirmed cart to `grocery_list_items` in DB

**Checkpointing:** Uses `MemorySaver` (in-process). For production, swap to `PostgresSaver` pointing at Supabase.

**Current status:** Agent graph executes end-to-end with **stub data** for Instacart catalog calls. Real Instacart integration pending API key setup.

**To visualize the graph:**
```bash
python scripts/visualize_graph.py
# outputs scripts/smart_grocery_graph.png + .html
```

## Pantry Vision Scan

`POST /pantry/scan` — multipart form upload (`image` field, JPEG/PNG/WebP, max 5 MB)

Uses Claude vision to detect pantry items. Returns detected items **without saving** — user reviews, then calls `POST /pantry/bulk` with `addedVia: "scan"` to save.

Graceful degradation: if `ANTHROPIC_API_KEY` is unset, returns stub data (testable without credentials).

## Gotchas

- `db/schema.sql` is auto-generated — edit migrations in `db/migrations/`, never the schema file directly
- The agent uses a **separate** async connection pool from the route handlers — both are initialized in the app lifespan in `main.py`
- Firebase service account key path: leave `FIREBASE_SERVICE_ACCOUNT_KEY` blank when deploying to Cloud Run (uses ADC automatically)
- `CORS allow_origins=["*"]` — restrict this before production
- Python version is locked at 3.13 via `.python-version`; use pyenv to match
